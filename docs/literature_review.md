# Literature Review: Agentic and Self-Correcting AI Systems for Automated Data Analysis

**Author:** Andrew Lee
**Scope:** This review situates the Self-Correcting Data Analysis Agent within four converging research threads — agentic reasoning and tool use, self-correction in large language models (LLMs), text-to-SQL as an executable analysis substrate, and autonomous data analysis and hypothesis generation. All twelve sources below were located and verified individually; each entry in the References section lists title, authors, year, and venue as confirmed against the ACL Anthology, NeurIPS/ICLR proceedings, or the primary arXiv/OpenReview record.

## 1. Motivation

Healthcare claims data are large, messy, and clinically consequential: costs cannot be negative, ages cannot exceed physiological limits, diagnosis codes are frequently missing, and readmission flags are often generated independently of cost. An analysis system that generates and executes queries autonomously must therefore do more than produce syntactically valid output — it must detect when a result is *wrong* and recover without human intervention. This is precisely the capability that recent work on agentic LLMs and self-correction has tried to formalize. The project this review supports implements that loop end-to-end: schema inspection, hypothesis generation, SQL planning, sandboxed execution, statistical and clinical validation, and bounded self-correction. The literature below both motivates that architecture and, importantly, bounds the claims one can honestly make about it.

## 2. Agentic Reasoning and Tool Use

The foundational shift enabling autonomous analysis is the reframing of an LLM from a text generator into an *agent* that interleaves reasoning with actions against an external environment. **ReAct** (Yao et al., 2023) established this paradigm, showing that prompting a model to alternate between reasoning traces ("thoughts") and task-specific actions produces a synergy: reasoning helps the model plan and revise, while actions let it ground those plans in real observations rather than hallucinated state. For a data-analysis agent, the "actions" are schema inspection and query execution, and the "observations" are the rows and errors that come back — a direct instantiation of the ReAct loop.

Where ReAct treats tool use as an emergent prompting behavior, **Toolformer** (Schick et al., 2023) demonstrated that models can be trained in a self-supervised manner to decide *which* API to call, *when*, and *with what arguments*, incorporating tools such as calculators, search, and question-answering systems. The relevant lesson for this project is architectural rather than a training recipe: the agent's reliability comes from delegating deterministic operations (query execution, keyword blocklisting, row caps, PII hashing, statistical tests) to trusted tools rather than asking the model to simulate them. The model decides *what* to ask; the tool layer guarantees *how* it is answered. This separation is what makes the deterministic components independently testable without any API key.

## 3. Self-Correction in Large Language Models

The core mechanism of this project — feeding a specific failure reason back to the model so it can rewrite a query — sits within an active and contested literature on LLM self-correction.

The optimistic case is well represented. **Self-Refine** (Madaan et al., 2023) showed that a single LLM can act simultaneously as generator, critic, and refiner: it produces an output, critiques that output, and revises it iteratively, improving results across seven tasks without any additional training or reinforcement learning. **Reflexion** (Shinn et al., 2023) generalized this into a framework where an agent verbally reflects on task feedback and stores those reflections in an episodic memory buffer to improve behavior on subsequent attempts, treating natural-language feedback as a substitute for weight updates. Both establish the plausibility of the iterate-until-correct loop, though both rely to varying degrees on the model's own judgment of quality.

The more directly applicable strand emphasizes *external, tool-grounded* feedback. **CRITIC** (Gou et al., 2024) argued that LLMs correct themselves far more reliably when they can verify outputs against tools — a search engine for facts, a code interpreter for programs — rather than introspecting alone. **Teaching Large Language Models to Self-Debug** (Chen et al., 2024) applied this specifically to code, including text-to-SQL: a model explains its generated program in natural language ("rubber-duck debugging") and uses execution feedback to identify and fix mistakes, achieving strong results on SQL, code translation, and Python generation. This project's design follows the CRITIC/Self-Debug philosophy rather than pure Self-Refine: the correction signal is not the model's opinion of its own SQL but a concrete, machine-generated failure code — `negative_cost`, `missing_column`, `aggregated_data_detected`, an execution error — produced by a deterministic validator. The practical consequence is that the retry prompt is anchored to something falsifiable: the model is not asked "is this right?" but told "this specific check failed, rewrite the query to satisfy it." That framing is what allows the loop to be bounded (a fixed maximum number of retries per hypothesis) and audited after the fact, because every trigger is logged with its failure category rather than left implicit in the model's reasoning.

That distinction matters because of the most important cautionary result in this area. **Huang et al. (2024)**, "Large Language Models Cannot Self-Correct Reasoning Yet," found that in the setting of *intrinsic* self-correction — where a model tries to fix its answer using only its own capabilities, with no external feedback — performance often does not improve and can degrade. This is a direct constraint on the honest framing of any self-correcting system: correction that works tends to be correction grounded in an external oracle. The validator in this project is exactly that oracle, and the project's claims are deliberately scoped to structural and data-quality errors (which the validator can detect) rather than to detecting domain-incorrect hypotheses (which it cannot). Citing Huang et al. is not a weakness in the review; it is what keeps the project's self-correction claims defensible.

## 4. Text-to-SQL as the Executable Substrate

Autonomous analysis over a database requires translating natural-language intent into executable SQL, a task with a mature benchmark literature. **Spider** (Yu et al., 2018) introduced the first large-scale, cross-domain, human-labeled text-to-SQL dataset — 10,181 questions over 200 multi-table databases spanning 138 domains — and established complex, cross-database generalization as the standard evaluation. It remains the reference point against which prompting-based methods are measured.

Two subsequent works are especially relevant to this project's design. **DIN-SQL** (Pourreza & Rafiei, 2023) showed that decomposing text-to-SQL into smaller sub-problems and adding an explicit *self-correction* step improves few-shot LLM accuracy by roughly ten points, approaching or surpassing fine-tuned state of the art. The self-correction module in DIN-SQL — re-prompting the model with the failed query to elicit a fix — is conceptually the same operation this project performs, differing mainly in that the trigger here is a clinical/statistical validator rather than a generic SQL-correctness check. **BIRD** (Li et al., 2023) then exposed the gap between benchmark and reality: on 95 large, noisy, real-world databases across 37 professional domains, the best model reached only ~55% execution accuracy versus ~93% for humans, and the benchmark introduced execution grounding and an efficiency metric (Valid Efficiency Score). BIRD is the sobering counterweight to Spider's optimism and is why this project validates on a controlled synthetic dataset and explicitly declines to claim generalization to real credentialed claims data without further validation.

## 5. Autonomous Data Analysis and Hypothesis Generation

Beyond single-query translation, a newer line of work targets the full analytical workflow. **Data Interpreter** (Hong et al., 2024) frames data science as a hierarchical graph of interdependent subtasks, generating and verifying code for each node and adapting dynamically as intermediate data changes. Its two contributions — hierarchical decomposition and programmable, self-verifying node generation — mirror this project's staged pipeline (inspect → hypothesize → plan → execute → validate → correct → report), and its emphasis on *verifying each subproblem* echoes the validator-driven correction discussed above.

The final thread connects autonomous analysis to *hypothesis generation*, the stage where this project asks the model to propose ranked, clinically interpretable hypotheses from a schema profile. In the general-science setting, work such as automated open-domain hypothesis discovery has shown LLMs can perform "hypothetical induction" — proposing explanations for observations — though novelty and validity remain difficult to guarantee. Most directly relevant is **Qi et al. (2024)**, "Large Language Models as Biomedical Hypothesis Generators," which constructed background–hypothesis pairs from biomedical literature, partitioned by publication date to avoid contamination, and found that LLMs can generate novel and validated biomedical hypotheses even on unseen literature — with multi-agent interaction and tool use improving diversity and zero-shot performance. This supports the project's premise that a model can propose meaningful hypotheses over health data, while the contamination-control methodology is a reminder that evaluation design determines whether such claims hold up.

## 6. Positioning and Gaps

Taken together, the literature justifies each architectural choice in this project and simultaneously constrains its claims. The agentic framing (ReAct, Toolformer) motivates the reason–act loop and the trusted tool layer. The self-correction literature (Self-Refine, Reflexion, CRITIC, Self-Debug) motivates the feedback-driven retry, while Huang et al. (2024) insists that this loop only works because correction is grounded in an external validator, not the model's introspection. The text-to-SQL literature (Spider, DIN-SQL, BIRD) both validates the executable-SQL approach and — through BIRD's real-world accuracy gap — explains why results on synthetic data must not be oversold. Finally, the autonomous-analysis and hypothesis-generation work (Data Interpreter, Qi et al.) situates the end-to-end pipeline and its hypothesis stage in current practice.

It is worth being explicit about what "verified" means for this review itself: every source was located by search and its bibliographic record checked against a primary index (ACL Anthology, the NeurIPS/ICLR proceedings, or the arXiv/OpenReview page) before inclusion, and no result, figure, or citation elsewhere in this repository is reported unless it was produced by an actual run or confirmed against such a source. That discipline is the methodological analogue of the validator the system itself relies on.

Three gaps remain honestly open. First, none of the self-correction methods reliably detect *domain-incorrect* hypotheses — a query can be structurally perfect and clinically meaningless — so the project's correction is scoped to structural and data-quality failures. Second, results on synthetic claims data do not transfer to real data without validation on a credentialed source such as MIMIC-IV or CMS public-use files (a point BIRD makes empirically). Third, the system performs descriptive and associative analysis only; nothing here supports causal inference. Naming these gaps explicitly, rather than papering over them, is what the balanced view of the literature — especially Huang et al. and BIRD — demands.
